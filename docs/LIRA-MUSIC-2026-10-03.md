## Что меняется для слушателя

- «Когда вышел этот трек, на каком альбоме?» использует метаданные текущего
  трека; явно названная пара исполнитель — песня имеет приоритет над плеером.
- Вопросы о стиле и исполнителе получают отдельный музыкальный поиск и короткий
  ответ с источниками, без непрошеной подборки радио или переключения звука.
- «Две похожие песни на Radiohead — Creep, радио не надо» ищет названия песен.
  Это текстовые предложения по источникам, не обещание их текущего звучания.
- Название без исполнителя, например Numb, требует уточнения вместо смешивания
  Numb и Numb/Encore. Неясное «кто он?» не переадресуется молча новому треку.
- Сбой поиска сообщается прямо; Лира не тратит model call на выдуманный ответ.

## Почему раньше справка не работала

Один ключ и один запрос давали HTML 403 с RU и HTTP 200 через NL. Проверены
тело с ключом, Bearer-заголовок, UTF/ASCII и curl; проблема зависит от egress.
Конкретную политику upstream установить не удалось. Ответ 401 без ключа сам
по себе не опровергал эту причину.

Использован существующий loopback/SSH путь Telegram relay: прямой Tavily 403
разрешает один bounded fallback к фиксированному HTTPS upstream. Секрет
конфигурируется только в API, проходит через relay в памяти, никогда не выходит
в браузер/логи. Нет нового сервиса, env-файла или постоянного туннеля.
После успешного fallback следующие запросы процесса используют relay.
Общий API deadline восемь секунд и logical daily cap сохранены.

Relay установлен на NL с резервной копией; соседние сервисы не перезапускались.
Telegram отвечает 401 на намеренно неверный токен и после отключения временных
диагностических SSH-процессов. Путь отката записан в RUNBOOK.

диагностика, не оценка интеллекта. После готовности permanent path вернул

Живой аудит выявил неверное превращение планируемого выпуска книги в год анонса
и третий трек при просьбе о двух. Устранён конфликт поздней общей инструкции
«по последним данным» с музыкальными правилами; итоговый контракт ограничивает
весь ответ и различает событие/дату. Повтор: биография без ошибочной даты книги,
ровно два предложения песен (Uno / Mr. Brightside), без радио/Play и без
«по последним данным». Субъективные сравнения по настроению остаются прозой модели.

**Граница:** проза модели не проходит детерминированную проверку каждого факта.
Источники помогают проверить ответ, но поиск может приносить слабые страницы;
субъективная похожесть не доказывает, что слушателю понравится песня. Нет анализа
звукового сигнала, физического iPhone/наушников или оценки долгого прослушивания.
