# Сохранённая песня → музыкальное продолжение Лиры

Статус: реализовано локально, проверено. Не принято
владельцем, не опубликовано. Ветка `codex/calm-home`.
Работа начата03.10, окончательные short-screen проверки завершены ночью04.10.

## Что меняется для слушателя

«Моё → Находки → Ещё → Спросить Лиру» открывает разговор с выбранной
сохранённой песней и тремя вопросами: «О песне», «Похожее», «Исполнитель».
Само открытие не отправляет вопрос, не читает станцию из каталога и не меняет
звук или очередь. Даже исчезнувший из каталога источник не блокирует разговор
о сохранённом названии.

Предмет виден над вопросами и полем ввода, отдельно от live-плеера. История
разговора сохраняется. Первый свободный вопрос явно называет находку в видимой
реплике; нажатие готового вопроса также явно называет её. Следующие свободные
сообщения продолжают диалог, позволяют исправить песню или спросить о текущем
эфире. Крестик убирает выбранную находку из поля ввода; он не удаляет находку
или историю. Повторное открытие той же или другой песни задаёт предмет заново.

## Контракт

Клиентский `requestChat` получает отдельный optional savedFinding без изменения
постоянного объекта находки. Нет нового поля в сетевом API: название включается
в **тот же видимый USER текст**, который записывается в чат и отправляется:

```text
О сохранённой песне «Linkin Park - Numb»:
Расскажи об этой песне
```

API распознаёт только точную рамку с отдельной строкой вопроса. Рамка остаётся
недоверенными пользовательскими данными. Транспортные команды, каталог и
разрешение действий читают тело вопроса: название «Pause Now» не является
просьбой поставить эфир на паузу. Фактический nowPlaying по-прежнему отражает
живой плеер; сохранённое название не подставляется туда скрыто.

Явно новая песня/исполнитель или просьба о текущем эфире меняет предмет.
Название без исполнителя уточняется; похожие песни сохраняют запрошенное
число. Replay ограничен доступными последними шестью USER репликами,
assistant текст и старое согласие Play не дают новое разрешение. Отдельный
saved предмет также передаётся существующему поиску текста/смысла песни,
не ломая ограничения цитирования.

Недостоверные metadata не превращаются в факт: UI показывает исходное
название и подсказку, готовые вопросы отключены. Первый свободный вопрос
передаёт canonical `Unknown`, чтобы не разбирать обрезанный рекламный текст
как песню и не подставлять live-трек. Пользователь может явно назвать песню.

Предмет потребляется синхронно в момент принятия отправки, а не после ответа.
Старый запоздалый ответ не поглощает новую находку. Retry повторяет исходный
вопрос ровно один раз и не включает ошибочный дубль USER в его историю.

## Проверки и визуальный просмотр

Бесплатные проверки поведения проходят настоящий клиент/API с подменённым
model/fetch, не оценивают качество музыкальной прозы. По коду выхода0:
source/test typechecks,900 API,24 offline (modelCalls0),905 webapp unit,
полная сборка. Полный serial functional:459 passed/7 skipped,13.2m,
`output/saved-find-functional.log`. После последних CSS отступов и добавления
persisted-history case — весь focused finds-lira10/10 и повтор test typecheck/
webapp build. Полный прогон без новой причины не повторялся.

Root лично просмотрел production-сборку с `VITE_AI_ENABLED=1`: 390×844,
834×1112, 1440×900; тёмную Aurora Field и длинное название на 390×450.
Ответ в визуальной фикстуре явно является заглушкой, настоящая модель не
вызывается. Плеер визуальной фикстуры на паузе; проверка сохранения играющего
плеера выполняется отдельно функциональными тестами с media mock.

## Ограничения и следующий шаг

Нет новой платной оценки в этом участке: предыдущие journals закрыты.
Тесты проверяют выбор предмета, запросы, ограничения действий и UI, а не
истинность будущего model ответа. Распознавания по звуку нет. Короткие
музыкальные ссылки разрешаются ограниченной грамматикой, это не обещание
понимания произвольной реплики. Пользовательские фоны вне просмотренной
Aurora Field в этом проходе отдельно не снимались.

Следом: показать владельцу конкретный вход из находки, затем отдельный
ограниченный выпуск принятого клиента без непринятой Studio истории.
Исследование новой возможности — [скриншоты и DeepSeek Vision](LIRA-DEEPSEEK-MULTIMODAL-2026-10-03.md):
это следующий предложенный участок, не реализованный в данном изменении.
