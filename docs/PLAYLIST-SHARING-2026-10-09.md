# «Моё» и ссылки на плейлисты — 09.10.2026

Статус: реализация и личный просмотр завершены локально, полный функциональный
прогон зелёный. Не опубликовано и не принято владельцем.

## Причина

Владелец снова сообщил, что production «Моё» неудобно, и запросил шеринг.
Проверка настоящего production на `b3255b3` подтвердила прежний порядок:
плейлисты выше избранного, находок, недавнего и очереди. Локальный ремонт
05.10 в production не переносился. Поле `isPublic` не открывало плейлист:
публичного API и сценария получателя не было.

## Участок и критерии готовности

1. Ежедневные разделы «Моё» доступны до плейлистов; избранное можно слушать
   целиком и вперемешку. Просмотр и возврат не меняют звук или очередь.
2. Владелец явно создаёт ссылку из плейлиста. Регистрация нужна отправителю,
   получателю для просмотра и прослушивания не нужна.
3. Ссылка публикует снимок выбранного плейлиста, а не всю медиатеку. Изменения
   личного плейлиста не публикуются незаметно: «Обновить» обновляет тот же URL.
4. Получатель видит порядок и доступность станций, запускает слушание явно,
   сохраняет независимую копию без смены текущего звука и очереди.
5. «Отключить ссылку» удаляет опубликованный снимок; повторная публикация
   создаёт новый случайный токен, прежний остаётся недоступен. Удаление аккаунта
   удаляет ссылки по FK cascade. При объединении аккаунтов ссылки удаляемого
   исходного аккаунта также прекращают работать.
6. Только имя, описание, упорядоченные station IDs и время обновления выходят
   через публичный API. Аккаунт, избранное, история и находки не передаются.
   Токены исключены из телеметрии, включая неверные и смешанные по регистру URL.

## Архитектура

Снимки хранятся в отдельной таблице существующего ACCOUNT_STORE SQLite, поэтому
переживают рестарт и выпуск. Не использовать новый файл внутри release.
До 24 действующих ссылок на аккаунт, до 128 станций в плейлисте — существующий
лимит плейлистов, не старый обрезающий лимит очереди 120. Отозванные снимки
удаляются целиком, не накапливая историю приватного содержимого.

Маршруты: POST `/me/collection-shares`, GET/DELETE
`/me/collection-shares/:collectionId`, публичный GET
`/share/collections/:token`. Все ответы uncached. URL получателя:
`/?playlist=<opaque-token>`; это возможность доступа для любого обладателя
ссылки, а не каталог всех пользовательских плейлистов.

Приёмочная проверка должна отдельно различать UI/очередь с media fixtures и
настоящий звук. Новая композиция требует просмотра владельцем до публикации;
всю `calm-home` выпускать нельзя.

## Проверки и ограничения

### Найдено при личном просмотре

- Ведущий плейлист на широком «Моём» растягивался по высоте соседней галереи
  до 575–700 px. Выравнивание по началу ограничивает панель содержимым;
  ежедневные разделы остаются выше неё.
- Светлый текст кнопок терялся на кремовом и тёмном фоне; метаданные компактного
  избранного также почти исчезали. Исправлены цвета в затронутых состояниях,
  включая пользовательский фон, без переделки выбранной композиции A.
- Обложка получателя на телефоне сжималась в узкую полосу, а действие копирования
  показывало ключ перевода. Исправлены размеры и RU/EN-подписи.
- Свежий авторизованный браузер получает плейлисты из облака без локального
  stationCache. Прежний экран не разрешал эти ID: станции и Play появлялись лишь
  после случайного посещения поиска. Теперь карта станций дополняется имеющимися
  избранными/недавними, а неизвестные ID загружаются только при открытии выбранного
  плейлиста, не более четырёх одновременно. Успешные ответы сохраняются в локальном
  кеше; смена аккаунта, плейлиста или уход с экрана отменяют применение поздних
  ответов. Полный порядок ID не меняется, недоступные станции не удаляются.
- Play с домашней карточки частично загруженного плейлиста раньше молча запускал
  только известную часть. Теперь он открывает плейлист для загрузки; звук затем
  запускается отдельным явным «Слушать». После завершения загрузки недоступная
  часть обозначена счётчиком, очередь содержит доступные станции в исходном порядке.
- Одна ещё не загруженная подборка оставляла пустую вторую колонку, а после
  расширения галереи её обложка раздувалась. Только для состояния без ведущей
  карточки введены ограниченные auto-fill колонки; в проверке 1440 px одна карточка
  занимает около 213×247 px. Обычная композиция A сохраняется.

### Границы доказательств

На локальном API проверены настоящие публикация и чтение снимка; браузерные
сценарии воспроизведения используют media fixtures и проверяют очередь/индекс,
а не слышимость. Физическое системное меню «Поделиться» на iOS/Android ещё не
проверено. Этот участок не доказывает исправление фонового Play на iPhone.
Отдельная локальная smoke-проверка настоящего API дала POST 200 → public GET 200
→ DELETE 204 → public GET 404; основной демонстрационный снимок сохранён.

Карточка предпросмотра ссылки в мессенджере с отдельной обложкой, совместное
редактирование и совместное синхронное слушание в этот участок не входят.
Открытие ссылки само по себе не запускает поток. По ссылке доступен именно
опубликованный снимок: независимые сохранённые копии после отзыва не удаляются.

Перед публикацией требуется просмотр владельцем и выборочный выпуск от master.
Вся `calm-home` содержит другие непринятые изменения и не является release candidate.
Ежедневная иерархия уже находится в локальном базовом коммите `2b9a228`, а не
только в текущем diff шеринга. Поэтому перенос одного нового коммита сам по себе
не доказывает исправление production «Моё»: в отдельном release checkout нужно
выборочно перенести эту зависимость, пересмотреть результат и повторить gate на
фактическом кандидате. Не заменять release-файлы целиком из calm-home.
