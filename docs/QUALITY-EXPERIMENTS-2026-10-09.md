# Проверки, которые нашли ошибки: 09.10.2026

Локальный участок в `RadioAtlas-codex`, `codex/calm-home`, поверх `c2f0285`.
Владелец разрешил добавлять и пробовать полезные инструменты после обсуждения
ECC. Main определяет контракт и проверяет; GPT-6 Luna реализует; независимое
ревью проверяет выводы. Production и платные модели в этот участок не входят.

## 1. Разбор сбоя звука из существующего журнала

Экспорт в настройках теперь дополняет исходные события полем `analysis`.
До 200 последних событий, до 10 последних попыток системного Play; фиксированные
метки наблюдений, без новых идентификаторов/названий/URL. Отдельно записаны
полученная команда, `playing`, движение времени, отсутствие источника,
ошибка и прерывание/восстановление контекста. Анализ выполняется при экспорте,
не в транспортных обработчиках. Хранение v1 и опциональность журнала сохранены.

Разбор не объявляет причину сбоя или слышимый звук. Неизвестный промежуток
обрывает атрибуцию; часы/смена источника обрывают сравнение времени. Окончание
окна и полнота доказательств различаются. Неисправный вход даёт безопасный
недоступный анализ вместо исключения.

Независимое ревью воспроизвело и Luna исправила: сравнение через отброшенное
невалидное событие; ложное восстановление suspended-контекста из active-сессии;
потерю `audio_error` без snapshot; полноту после отката media time; сравнение
через повторный старт записи. Main также исправил через Luna сбрасываемый факт
source reset и область summary для последних 10 попыток. Узкие unit: 29/29.
Финальное независимое ревью не нашло оставшихся существенных дефектов.

Main прошёл настоящий локальный UI5184: Настройки → Для разработчиков →
Диагностика → начать → остановить → скопировать → закрыть. Отчёт содержит
`analysis`, запись остановлена, выбранный Deutschlandfunk остаётся на паузе.
Ни станция, ни очередь не переключались. Физический iPhone не проверялся.

## 3. Stryker: проверяем тесты очереди

Dev-only Stryker core/runner 9.6.1 с существующим Vitest 3.2.4. Только
`shuffleStations.ts`, concurrency 1, без incremental, dashboard и загрузок.
JSON/HTML локально, sandbox под игнорируемой `.tmp`; env-файлы исключены.
`thresholds.break=0` намеренно оставлен экспериментальным: exit 0 не значит,
что все намеренные ошибки пойманы.

Первый замер: 78 мутаций, 41 killed/35 survived/1 uncovered/1 timeout.
Main отклонил промежуточный golden-тест точной PRNG-перестановки: контракт
не обещает конкретный порядок для данного seed. Усиливаем сценарные проверки
первой/невалидной позиции и повторного перемешивания частично изменённого хвоста.
Финальный машинный отчёт: `.tmp/quality-experiments/mutation/mutation.json`.
Разбор survivors выявил ещё один существенный пробел: тесты не замечали
полностью отключённое перемешивание. Добавлена проверка разнообразия по
нескольким seed без golden-перестановок, плюс случаи невалидного индекса
и повторного перемешивания без текущей станции. Обе мутации «не перемешивать»
теперь убиты новым тестом.

Финальный замер после сценарных тестов: 1м45с, 78 мутаций — 64 killed,
12 survived, 1 uncovered, 1 timeout, 0 errors; score 83.33% (covered 84.42%).
Узкие тесты: 17/17. Sandbox уменьшен с 5797 до 400 файлов.
Промежуточный отчёт с отклонённым golden-тестом сохранён
как `mutation-before-tests.json`; он не является результатом итоговых тестов.
Выжившие мутации нужно разбирать, а не скрывать исключениями ради 100%.
Среди них изменения констант PRNG и граничных ветвей: конкретная перестановка
не обещана контрактом. Один timeout относится к мутации бесконечного цикла,
а не к обычному тесту. Полное покрытие качества очереди не заявляется.

Добавления пакетов ограничены dev-инструментами; версии прежних runtime
пакетов сохранены. У нового Stryker→typed-rest-client→qs 6.15.1 остаётся
moderate npm advisory. Попытки узкого override не изменили фактическое дерево;
неэффективный override удалён. Не считать инструмент безуязвимым; пилот
работает только с доверенным локальным кодом, без сетевого reporter.
Остальные существующие npm advisories требуют отдельного разбора достижимости,
не массового `audit fix` в этом участке.

  924 API, 94 bot, 105 scripts + 1 skip (нет rsync), 981 web units.
  После окончательного усиления тестов повторены test typecheck и все

  105 passed + 1 skip. API/bot без изменений повторно не запускались.
- `npm run build`: exit 0. Dev-инструменты не импортируются приложением;
  поиск их имён в итоговых JS assets совпадений не дал.
- `npm ci --dry-run --ignore-scripts --no-audit`: exit 0. Это проверка плана
  установки по lockfile, не доказательство чистого `npm ci` на другой машине.
- Полный функциональный Playwright: **exit 1**, 494 passed, 7 skipped,
  1 failed за 15 минут. `nav-clearance.spec.ts` (globe) не дошёл до Глобуса:
  при открытии Главной `[data-home-feed-entry]` не появился за 15 секунд.
  Исходный HTML report сохранён в `functional-first-report/` рядом с логом.
- Воспроизведение того же теста: `--repeat-each=12 --workers=6
  --trace=retain-on-failure`, 12/12 passed за 59.9с. По правилу репозитория
  это диагностический стресс-прогон, не добавленные retries. Таймауты,
  допуски и исходный тест не менялись. Причина первого падения не установлена;
  **полный функциональный gate остаётся красным**, а не «починен повтором».

## Что не подключено и почему

Context7 пока не даёт доказанного преимущества над чтением официальной
документации для этих задач. Semgrep полезен при конкретном классе ошибок,
но отдельного набора правил ещё не обосновано. ECC целиком, глобальные hooks,
автономные внешние агенты и платные сервисы не установлены.

Перед выпуском требуется разобраться с неподтверждённой стабильностью старта
Главной и получить зелёный полный functional gate. Этот участок фиксируется
локальным коммитом экспериментов, не как готовый production release.

Следующий продуктовый участок: избранное/недавнее и возврат в свой набор из
Ленты по действующей карте. Новые проверки применять там, где они дают сигнал,
а не развивать систему инструментов бесконечно.

Источники для границ пилотов:
[Playwright accessibility](https://playwright.dev/docs/accessibility-testing),
[axe-core](https://github.com/dequelabs/axe-core),
[Stryker Vitest runner](https://stryker-mutator.io/docs/stryker-js/vitest-runner/).
