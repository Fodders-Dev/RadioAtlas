## Зачем

Слушатель просит быстрый звук как Sonic, получает сразу несколько источников
и может их быстро менять. Пояснение должно помогать выбрать между ними.
Повторять название жанра с красивыми эпитетами недостаточно. При этом каталог
не знает, что прямо сейчас звучит, и не доказывает отсутствие речи или рекламы.

## Наблюдаемые дефекты

Сырые примеры сохранены в `docs/evals/lira-card-facts-2026-10-02-*.json`:

- named-final3: jungletrain без подтверждённых тегов описан как «чистый нон-стоп,
  без лишних жанров». Надпись в имени не доказательство живой программы.
- constrained: «без лишних разговоров» для Caprice. Это не установленный факт.
- unknown: станция с длинным перечнем keywords в имени попала в подборку
  «неон/ночной город». Само длинное имя ещё не делает её неподходящей;
  нужен сравнительный тест релевантности и фактический формат.

`catalog/service.ts` computeSearchRelevance суммирует совпадения q/tag и затем
смешивает score с quality. При пустом q даже relevance:true идёт через seeded
browse. Это гипотезы для проверки, а не доказанный корень каждого примера.

## Порядок работы — один законченный участок за раз

1. Бесплатно воспроизвести выбор на небольших независимых fixtures через
   настоящий catalogue adapter: точный жанр против keyword-name, tag-only
   запрос, настроение против жанрового формата, близкий вариант против
   контрастного. Проверить реально отправленные аргументы planner/search.
   Не читать/копировать файлы production каталога; использовать API.
2. Исправить только подтверждённый дефект ранжирования. Сохранить страну,
   No Play, количество, исключения до cap и явный поиск конкретной станции.
   Если общий поиск меняется, обязательно защитить обычный Search отдельными
   контрактами. Не штрафовать имя просто за длину/язык и не выдумывать качество.
3. Выделить частные основания пояснения: station UUID + подтверждённые жанры,
   страна, общие/отличающиеся теги. Отсутствие evidence — честное отсутствие
   описания формата. Оценить ограниченное структурированное compose с ссылками
   на собственные evidence вместо очередного словаря запрещённых эпитетов.
   Не выводить приватный evidence наружу; публичный allow-list прежний.
4. После source/test typecheck, полного API и offline contracts — независимое
   ревью существенного изменения. Настоящая модель только с новым бюджетом,
   offline preflight и закрываемым ledger. Сценарии с именованными разными
   карточками, уточнением «быстрее», «совсем другой стиль», русской страной,
   отсутствием тегов и немузыкальной репликой. Без автоматического play.

## Приёмка

- Найденные источники действительно соответствуют подтверждённым требованиям;
  top-name keywords не вытесняют прямое жанровое evidence в fixture.
- Пояснение каждой станции имеет её UUID и основание в её собственных данных;
  неизвестные свойства и текущая программа не превращаются в факты.
- «Контраст» отличается по известным жанровым признакам, «ближе» сохраняет
  известное общее; если каталога не хватает, число вариантов честно меньше.
- Правка не замедляет свайп, не переключает звук без просьбы, не сбрасывает
  очередь, не создаёт параллельных full-catalog rebuild и не требует нового UI.

Сильный результат — слушатель понимает различие и сразу пробует следующий
источник. Красивый ответ без полезного выбора не считать успехом.
