# Следующий участок: разговор без выдуманного музыкального намерения

Основание: живой semantic campaign 02.10.2026, ledger закрыт. Этот участок
сначала бесплатный: код, фикстуры, анализ сохранённых ответов. Новый бюджет
для модели этим документом не разрешается.

## Наблюдаемая ошибка

В `lira-semantic-directions-sonic-nonmusic-2026-10-02T13-06-15-668Z.json`
planner дважды правильно выбирает `intent: chat` без инструментов.
На «Хочется вечером пиццы» composer предлагает музыкальный саундтрек.
На «и?» приписывает ожидание эфира и объясняет отсутствие проверенных станций,
хотя пользователь станций не просил и поиск не выполнялся.
Карточки/действия уже безопасны; ошибка находится в содержании разговора.

## Конкретная точка диагностики

`composeAgentReply` в `apps/api/src/ai/brain.ts` безусловно добавляет system
grounding про станции, включая «Если нет ни станций, ни ссылок, честно скажи,
что подобрать не удалось». Для `chat` без поиска эта инструкция описывает
несуществовавшую задачу. Planner intent сейчас не передаётся composer как
различение обычной беседы и неудавшегося музыкального поиска. Это подтверждённый
конфликт инструкций, но не доказательство единственной причины всех ответов.

## Ограниченное исправление и проверки

1. Передавать доверенный итоговый контекст ответа: обычная беседа, справка,
   реальная подборка с результатом, выполненный поиск без результата.
   Определять его по planner gate и фактическим наблюдениям; не доверять
   свободной записке модели и не выводить intent из текста ассистента.
2. Разделить общую честность (не выдумывать станции/действия) и инструкции
   неудавшегося поиска. Последние применять только к реальному поиску/подбору.
3. В обычной беседе отвечать на текущую человеческую реплику. Не превращать
   любой бытовой контекст в станционную просьбу. Короткое уточнение продолжает
   тему пользователя, а не навязанное предложение ассистента.
4. Фикстуры через настоящий brain и захват composer messages: пицца → «и?»;
   приветствие; музыка под пиццу (явная подборка); справка о DnB; запрос без
   результатов; переход музыка → бытовой вопрос и обратно; отказ от подбора.
   Проверять различение контекстов и сохранение tool/action safety. Mocked prose
   не считать доказательством качества настоящей модели.
5. Не добавлять обязательный model call, постфактум модельную оценку или
   список regexp для каждой бытовой темы. Не менять интерфейс Studio.

Отдельно зафиксированный следующий риск: repair пяти карточек может потратить
шесть tool slots на поиск и разрешение прежних UUID, не выполнив второй
семантический поиск. Решать отдельным ограниченным участком после разговора;
не повышать бюджет инструментов или память сервера без измерения.

Приёмка: оба typecheck, API suite, offline evaluator без model calls;
независимое ревью изменений маршрутизации. Реальные ответы проверять только
после нового согласованного бюджета. Старая оценка $0.24623148 не переносится.
