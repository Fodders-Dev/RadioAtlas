# Лира: пояснения текущих карточек и новые источники при повторе

02.10.2026. Серверный участок поверх опубликованного `e50ccdb`.
Новая композиция Lira Studio в этот выпуск не входит.

## Результат для слушателя

- Composer получает окончательный список карточек. Пояснение привязано к
  названию станции и её собственным тегам, а не к меняющейся позиции.
- Короткие «и?»/«ещё» продолжают музыкальную просьбу, сохраняя количество,
  страну и запрет запуска. Исключаются прежние UUID и подтверждённые зеркала
  по точному потоку либо нормализованному названию с известной страной.
- Фильтрация работает до лимита поиска, включая поиск по имени артиста.
  Краткий повтор с текстом о прежних карточках или без названий текущих
  получает фактическое описание новых карточек. Состояние звука не меняется.
- Немузыкальная реплика не заставляет загружать станции из истории.

Это узкие проверки результата, не универсальная проверка всех музыкальных
утверждений модели. Смысловые различия Classic/2, неизвестные страны и разные
URL с query не объединяются по совпадению бренда.

## Проверки

Оба общих typecheck, финальные API source/test typecheck и API build: exit 0.
Полный API: **750/750**, exit 0. Offline: **21 контракт**, ноль model calls.
Проверены UUID после границы 128, зеркала и догрузка страниц до cap, related/
near/requiredGenre/artist ветки, отказ lookup, positional prose, stale prose,
пропавшие прошлые строки, No Play, смешанные жанры и немузыкальный повтор.
Независимое ревью Astra выявило и помогло устранить дефекты этих границ.

Критичный риск памяти: параллельные 128 lookup на холодном реальном
createCatalogService воспроизводили 128 перестроений каталога/индекса.
Последовательные lookup дают одно перестроение. Все явные UUID исключаются;
сопоставление зеркал разрешает только первые 128 уникальных ID. Provider и
boundary могут вместе сделать 256 тёплых lookup; синтетический срез 66k строк
занял около 170–214 ms. Это не замер production latency.

## Настоящая модель и бюджет

Отдельный согласованный лимит **$3**, DeepSeek v4 Pro на RU. Кампания закрыта:
**15 пользовательских реплик, 36 вызовов, upper $0.10856736, reserved 0**.
Цена рассчитана по верхним peak cache-miss тарифам
[официального API](https://api-docs.deepseek.com/quick_start/pricing/).
Web calls и исполнение действий клиента отсутствовали; ключи оставались на VPS.

| Диалог | Карточки / результат |
| --- | --- |
| Скорость как Sonic → «и?» → «ещё три» | Финальный повтор 3 → 3 → 3; девять разных подтверждённых источников, описание текущих названий, только open-station |

| Пицца вечером → «и?» | 0 → 0, без station tools |

Первые два прохода Sonic сохранены: они выявили новые карточки со старым
текстом и затем пустое «карточки ниже». После исправления третий проход зелёный.
Последняя маленькая правка также покрывает отсутствие прошлой строки каталога;
она проверена полным API, а unknown/nonmusic пройдены на точном финальном bundle.
Последний Sonic/constrained проход отличается от него только этим деградированным
guard, который не влияет на подтверждённые предыдущие строки этих сценариев.

Harness запускает настоящий brain на RU с настоящей моделью и loopback HTTP
каталогом, после offline preflight. Он не является браузерным запросом к
/api/ai/chat; country adapter ограничен пятью страницами по 100 строк, не
доказывает паритет полного production каталога/профилей. Воспроизведение аудио,
физический телефон и наушники не проверялись. UI этим участком не меняется.

## Ограничения и следующий участок

Подбор всё ещё может приносить станции с раздутым keyword-name. Модель иногда
пишет «чистый nonstop» или «без лишних разговоров» без достаточного evidence;
узкие guards не доказывают текущую программу, темп или отсутствие речи.
