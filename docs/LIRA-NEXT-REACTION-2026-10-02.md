## Почему это происходит

Продолжение выбирается lexical admission до planner: recommendationContextTurns
собирает прежние ограничения только для распознанных фраз. Country/repeat
wrappers также создаются до semantic planner. Поэтому даже правильная жанровая
гипотеза уже получает record без страны и прежних ограничений. Добавление
синонимов «помягче» или только новая composer-инструкция оставят эту причину.

## Направление реализации, рассмотренное Astra

1. Перед существующим planner давать bounded USER-only candidate history:
   исходные просьбы, промежуточные темы и текущую реплику. Candidate не означает
   согласия на подбор. Прежнее предложение ассистента не активирует музыку.
2. В существующем JSON plan принять небольшое continuity-решение continue/new,
   имеющее смысл только при accepted intent recommend. При нескольких целях
   возможен ограниченный reference на USER-request, а не на assistant promise.
3. **До первого инструмента** разрешить один request-scoped selection context.
   Continue сохраняет применимые страну, явные запреты, количество, repeat IDs;
   последняя реакция меняет музыкальную цель. Текущая явная страна/число/снятие
   ограничения выигрывают. New начинается заново. Фильтры и composer получают
   один и тот же context, вместо отдельных трактовок.
4. Прямые детерминированные маршруты сохранять, но свести их к тому же context.
   Не добавлять отдельный classifier call, stored taste, новый UI или словарь
   жанров из прилагательных. Запуск отделён: continuation не продлевает старое
   разрешение Play. Missing/malformed continuity на неоднозначной реакции
   не должно молча запускать глобальные станции без прежних ограничений.

Цена: некоторые ранее пропущенные реакции должны входить в существующий planner.
Нет новой обязательной фазы на каждый запрос, но обещать одинаковое число
model calls для вновь поддерживаемых реакций нельзя. До платного прогона
зафиксировать calls/limits в бесплатных тестах; предыдущий ledger закрыт.

## Приёмка

- Четыре свободных реакции из таблицы продолжают пользовательский подбор,
  сохраняют Russia/no-news/count=2/NoPlay и fresh cards; bounded batch один.
- Два запрошенных направления представлены, если оба есть в fixture-каталоге.
- Music→pizza/exam→и?, decline и knowledge не оживляют selection/batch/play.
- Новая страна/число, явное снятие запрета и явно новая музыкальная просьба
  обновляют context, старые ограничения не побеждают текущую просьбу.
- Прежние самовольные музыкальные предложения ассистента не достаточны для continue.
- Missing/malformed decision, planner failure и отсутствие прежней просьбы:
  bounded conservative outcome, без безусловного global search.
- Проверить реальные runner/provider, response/action gates и бюджеты; не
  менять телеметрию на основании непроверенных пользовательских строк.
- После типов/API/offline, независимого review — новый live campaign только
  с согласованным бюджетом, затем same-SHA CI и публикация.

Принятого нового визуального решения в этом участке нет. Полезность для
слушателя и реальное понимание разных формулировок должны проверяться отдельно.
