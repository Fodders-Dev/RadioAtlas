# DeepSeek: что мультимодальность может дать Лире

Исследовано 03.10.2026 по официальным материалам, без платных запросов.
Это предложение следующего участка, не реализованная функция и не смена модели.

Обновление04.10: предложенный сценарий реализован локально и проверен на семи
настоящих запросах. [Результат и ограничения](LIRA-MUSIC-IMAGE-2026-10-04.md).
Разговорная модель не менялась. По просьбе владельца дальнейшее расширение
Лиры отложено; следующий приоритет — интерфейс и UX.

## Подтверждённые возможности

Текущая таблица API называет `deepseek-flash` моделью **DeepSeek-V4.1-Flash**:
текст и изображения на входе, текст на выходе. `deepseek-v4-pro` в актуальной
таблице — V4-Pro-0813, без Vision. Старые Flash/Flash-Vision-Exp имена временно
направляются на V4.1 Flash. В исходном объявлении обещалась замена Pro, но
последующий changelog оставил Pro доступным: нельзя переносить старое обещание
на нынешнюю конфигурацию.
[Модели и цены](https://api-docs.deepseek.com/quick_start/pricing/),
[модальности API](https://api-docs.deepseek.com/api/list-models/),
[история изменений](https://api-docs.deepseek.com/updates/).

Vision читает картинки и текст на скриншотах. JPEG/PNG/GIF/WebP передаются
через Chat Completions как блоки, включая inline base64; совместимый Responses
API тоже принимает изображения. Максимум 1024 входных токена на картинку;
сама картинка и окружающий текст тарифицируются. Это не оценка фактической
стоимости полного диалога.
[Vision](https://api-docs.deepseek.com/guides/vision/).

В опубликованных модальностях нет аудио. Поэтому по этим материалам нельзя
обещать, что Flash слушает радио, распознаёт песню, голос или напев и анализирует
темп по аудиозаписи. Для таких функций нужен отдельный проверенный тракт
распознавания. Janus-Pro умеет понимать/генерировать изображения, но это
отдельная серия открытых моделей, не функция текущего Flash chat API.
[Модальности](https://api-docs.deepseek.com/api/list-models/),
[Janus](https://github.com/deepseek-ai/Janus).

## Что есть в нашем коде

`apps/api/src/ai/modelClient.ts`: `ModelMessage.content` сейчас строка;
клиент отправляет текстовые сообщения в Chat Completions. Загрузка изображения
и типизированные image blocks не реализованы. В `index.ts` default DeepSeek
model — `deepseek-v4-flash`: по документации этот alias ведёт на V4.1 Flash,
но окружение может его переопределять. Активную production конфигурацию этим
исследованием не проверяли и не меняли. Смена имени сама по себе не включает
приём изображений в нашем продукте.

## Рекомендация для продукта — вывод из возможностей, не обещание качества

Первый полезный сценарий: **скрин песни или плейлиста → подтверждение
исполнителя/названия → музыкальное продолжение Лиры**. Человек приносит музыку
из другого приложения без ручного переписывания. Лира затем предлагает уже
понятные действия: о песне, похожие песни, исполнитель. Распознанный текст
остаётся проверяемым предметом диалога, а не подменой live nowPlaying.

Второй сценарий — фото обложки/винила: прочитать подписи, предложить кандидата,
проверить его источниками. Сходство изображения не доказывает альбом/издание;
при нечитаемом тексте или нескольких кандидатах спрашивать, не выдумывать.
Подбор «музыки под картинку» возможен как субъективная интерпретация настроения,
но менее прямой вклад в музыкальное открытие; не начинать с него.

## Один ограниченный будущий участок

1. Один PNG/JPEG/WebP из файлов/скрина, предпросмотр и удаление до отправки.
   Ничего не отправляется по одному выбору файла. Не новая галерея/редизайн чата.
2. API принимает ограниченное изображение, проверяет фактический формат,
   размер и декодируемость. Проектный лимит значительно меньше provider max;
   не проксировать произвольные пользовательские URL. Ограниченная параллельность
   и время, чтобы не возвращать серверные проблемы с памятью.
3. Тракт vision извлекает кандидатов с неопределённостью. Видимый текст картинки
   — недоверенные данные, никогда разрешение Play/очереди/удаления.
4. Показывать кандидата и дать исправить/выбрать его, затем пользоваться
   существующим музыкальным продолжением. Нет автоматического Play и добавления
   всех строк скрина в коллекцию; нет обещания доступа к трекам на demand.
5. Не сохранять сырое изображение в общем chat/localStorage/телеметрии.
   Перед отправкой понятно показать, что выбранное изображение уйдёт AI provider.
6. Бесплатные contract/security/UI checks, затем отдельный согласованный
   бюджет: разборчивые и смазанные скрины, кириллица, длинные названия, несколько
   треков, отсутствие музыки, попытка команды внутри картинки, живое переключение
   эфира. Измерить верность извлечения, ложную уверенность, время и расход.

До этих проверок не обещать качество OCR, поиск по звучанию или улучшение
музыкальных знаний от одной лишь смены модели. Нынешняя работа с сохранённой
находкой заканчивается своим отдельным проверяемым участком.
